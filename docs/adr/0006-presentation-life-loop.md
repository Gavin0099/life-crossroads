# 0006：生活播放不成為第二個模擬時鐘

2026-10-24，LIFE-LOOP-01 / WORLD-ART-01。延續 ADR 0001～0005 的純 Swift、保存先於發布、原局不可變與唯讀視覺邊界。共同凍結 PR #8 `c136beb`，不改 RNG-V2 或存檔版本。

`LifePlayback` 是不持久化的呈現狀態機，`living → event → consequence → living/ended`。正式 `LifeSession` 先經既有推進與原子保存，選定下一事件；播放才呈現兩個決策年齡之間的生活。250ms pulse、1/3倍、暫停及跳過只改此狀態機，不取得亂數、不執行決策、不寫檔。事件到達時一定停住，只有玩家選項能改人生；決策或推進寫入失敗，舊世界與舊檔保留。

首頁、背景與資料說明會暫停；恢復到前景不自動追趕。程序重開從正式存檔中的事件或結果停住，不保留動畫位置，也不補算離線時間。因為下一事件早已選定，重開可能直接顯示該事件，這是明示的恢復語意，不是離線成長。若未來要恢復逐格位置，須另提呈現快照規格，不能把真實時間混進 Seed。

整合覆核另發現既有確認框接縫風險：dismiss setter 清除 optional 請求，按鈕回呼卻再讀相同 optional。改用 iOS15 已有的 `presenting:` 捕獲非空請求，取消仍只清除請求。這是源碼中的狀態依賴修正，不能當作已觀測轉場失敗的根因。

該次原生失敗的 UI 階層確實已在新人生的 living 階段，跳過控制也存在；測試先前只查詢單一轉場畫面，錯過控制後等待5秒，比8秒旅行短。helper改為等待真實控制出現再跳過，原本事件與資料斷言不變；真正未執行的重新開始仍無法通過。另以取消前後原檔不變、三種確認動作清除舊決策及正確 Seed 驗證請求捕獲。

`LifeWorldViewState` 是 Gameplay 擁有的單向畫面契約。角色、故事物件及選擇日記來自實際 session/trace/story facts；尋求協助不等於已獲支持。最近選擇日記讓沒有故事旗標的8歲事件也能留下實際痕跡。虛構河畔的光線與走動只是演出，不能推導國家實景、因果或機率。Visual World 只新增 `LifeWorldScene`，主流程單點整合，不讓兩個角色同改 `CrossroadsView`。

完整人生仍有15個重大決策，原有比較、分岔、存讀與詳細紀錄保留；生活場景常駐在可捲動內容之外，事件時縮小以讓出操作空間。最大字體使用直排控制，減少動態效果不做插值。驗證包含兩事件自然到達、失敗後重試、完整人生/分岔回歸及不同播放方式下的 Seed/trace 不變。這些工程證據不替代真機、人工 VoiceOver、兒少節奏與美術選稿。
