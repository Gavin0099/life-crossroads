# LC-04 W1／W2 定向驗收

依使用者 2026-10-24 整合決策，在 PR #5 的 `2f030d2` 上補強兩項測試；維持既有引擎、事件目錄、分岔及圖片邊界。W1／W2 與最新 CI 通過後可合併 main，不以此次合併宣稱 P1 或發布通過。

## W1：保留原人生與兩側實際資料

- 固定日本／家庭一／Seed 0，從原局選擇回饋擷取事件文字及 ID、行動文字及 ID、四項資源選前／選後值。預期資料來自分岔之前的實際操作畫面，不重新呼叫引擎製造 expected。
- 13 歲線上改紙本後，先確認兩條路線的行動與資源確實有差異，避免錯接兩路仍通過。
- 分岔後與替代局結束重開 App 後，各自核對原人生 8／32／80 歲的完整紀錄。
- 比較頁核對 13／32／80 歲兩側的事件、行動及實際四項資源；保留 12 段到 80 歲的完整對照與後續人工改選說明。
- 為既有畫面加穩定 accessibility identifiers；資源的 accessibility value 描述實際選前／選後數字，沒有新增模擬規則。

## W2：寫入失敗、畫面保持與重試

- 僅 Simulator 編譯且以 `-ui-testing` 啟動時，`-ui-fail-save-at 2,4` 會在指定保存嘗試拋出寫入權限錯誤，一次消耗後即可重試。正式裝置編譯不包含注入程式或測試校驗畫面。
- 第一次建立人生正常保存，接著讓「選擇」及「繼續」各失敗一次。測試確認真實錯誤 alert 出現、原事件或回饋畫面保持、實際存檔 bytes 的 SHA-256 不變。
- 解除該次故障後，玩家重按同一操作成功；檔案 SHA-256 改變，重啟 App 可讀回成功重試的進度與同一份檔案。
- 此注入驗證 GameStore 的保存失敗處理及畫面接線。SaveRepository 的真實檔案替換失敗，另由前輪獨立 reviewer 的唯讀目錄探測驗證；不把注入當成涵蓋所有 iOS 磁碟故障。

## 驗證與界線

定向 Simulator 指令為 `bash artifacts/evidence/lc04-w12/run-focused-ios.sh`，使用獨立 iPhone SE 第三代／iOS 27 裝置，成功或失敗均 shutdown 並 delete。CI 仍執行完整 Swift、Python 與 UI suite。

啟動壞檔與分岔選擇器寫入失敗提示的 UI 回復、分岔頁最大字級、人工 VoiceOver、實機、兒少理解與節奏仍依後續驗收處理。完整人生比較的摘要視覺改造由圖片工作線接手，本輪沒有混入未核准素材或改寫因果說明。
