# LC-05：事件多樣性與資源平衡量測

基準為 PR #3 的 `4f268b8d195c212ab32da5c7471016b9f9646b9f`。獨立 [Review 5626995543](https://github.com/Gavin0099/life-crossroads/pull/3#pullrequestreview-5626995543) 已確認工程整合成立，產品仍 Draft／HOLD。本文是 RNG-V2-01 的基準契約：先檢驗三個樣本是否掩蓋事件重複與後期資源封頂，在舊版基準保存前不改23個事件或現有平衡；後續RNG-V2再以相同測試格作新舊比較。

## 預定樣本與策略

日本、美國、印度、肯亞，各兩個現有家庭情境；每背景使用投入優先、求助優先、休息優先及穩定亂數多樣選擇四種策略，各跑 Seed 0～31，合計 1,024 局。所有策略只提交當時可行的選項，記錄實際 choice ID 分布，不能以策略名稱替代執行事實。多樣選擇使用獨立的分析亂數 channel。

這是一個均衡的測試格，家庭和策略權重是實驗安排，不代表各國家庭或玩家分布。四個策略不窮舉所有選擇，32 個 Seed 也不是整個狀態空間。遇到無法完成的人生立即回報錯誤，不把失敗樣本排除後只統計成功局。

## 指標契約

- 事件出現率：以該年齡的機會數作分母；另報符合條件的次數與入選／符合條件比率。所有候選都保留，零次符合與符合但未抽中分開閱讀。零分母顯示無可估值，不填 0%。
- 每局差異：同國家、同家庭、同策略下所有不同 Seed 的無序配對，每 cohort 有 32×31÷2＝496 對；以同年齡位置不同的事件 ID 數量為距離，保留距離 0。另以事件 ID＋故事變體計算，不能把同事件的分岔冒充新事件。
- 策略差異：同國家、同家庭、同 Seed 的六種策略配對，每配對 32 對；固定背景及環境亂數，但不同策略可能改變事件資格，這些差異是模型內的結果。
- 資源飽和：四項資源分開統計最終分布、曾到 100、首次到 100 年齡與每個決策年齡的選後 100 比率。不合成一個人生分數。
- 實際增益：讀取 trace 的上限截斷，立即選擇與時間跳躍分開統計。正向增益指截斷前的淨變化；正負效果互相抵銷不算上限造成的損失。保留實際前後值和被截掉的點數。
- 延遲呼應：列出該次跳躍真正觸發的來源事件與選項；多個呼應同時碰到上限時，只能將損失歸於這組呼應，不能任意切分到個別人物或選項。

## 驗收與執行

先以手算例子測試分母、零差異、上限／下限、淨零效果及多個延遲呼應，再用正式引擎跑完整樣本。機讀報告需包含分析與遊戲版本、Seed、背景、策略和精簡逐步紀錄；可讀表格由同一 JSON 產生。正式樣本重跑的 JSON 必須一致。

```sh
swift run -c release life-demo --batch-report --seed-count 32 > artifacts/evidence/lc05-baseline/batch-report.json
python3 scripts/render-batch-report.py artifacts/evidence/lc05-baseline/batch-report.json artifacts/evidence/lc05-baseline/report.md
```

命令參數與輸出以實作及測試為準。CI 使用較小的預定 Seed 0～3（128 局）檢查批次管線，完整 1,024 局以本片保存的證據為準；不得把縮小的 CI 樣本當作完整基線。Swift／Python 測試負責量測正確性，App 與 Domain 沒有產品規則改動時不額外建立本機 Simulator。

## 量測後的決策邊界

事件是否新增，要根據低變化的年齡槽、未達條件的原因及可探索的人物／行動來提出假設。資源是否調整，要先分清楚選擇本身、支持與延遲呼應何時消耗完上限空間。不要先壓低或提高數值，只為讓分布看起來平均。

批次報告可以證明哪些內容在這個樣本中出現、如何重複、哪些增益被截斷；不能證明孩子覺得新鮮、想玩第二局或理解環境和選擇。實機、人工 VoiceOver、10～15 分鐘節奏與分齡兒少試玩仍另待驗收。完整 50～70 事件及八國 P1 目標保持不變。
