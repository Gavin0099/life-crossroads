# LC-04：回到岔路與完整後半生比較

基底：`main@5701a36`。本片獨立 Draft PR，等待 review，不合併或發布。圖片工作維持獨立分支。

## 玩家實際操作

1. 玩完一段人生，在回憶冊選「回到一個重大岔路」。15個已發生的重大決策均可選，包括第一項與最後一項。
2. 查看當時真正可用的選項及成本。原選項標示不可重選，不可行選項顯示原因；引擎也拒絕繞過。
3. 改選後從這一頁的回饋繼續，後續每一步由玩家親選。原人生完整保留，可隨時查看並回到試走進度。
4. 走到晚年，查看從岔路到80歲回顧的每一個時點：人物、事件、選項、選前／選後四項資源、延遲呼應及實際原因。資源不合成人生總分。
5. 每次有效操作先原子寫入本機，再更新畫面。關閉 App 後由首頁續玩。建立新人生必須確認，會取代目前這組人生；不是多存檔收藏系統。

這次改選之後仍有新的人工決策；比較頁明示後續不同事件／行動數，不把所有差異歸因於最初的一個選擇。相同種子只讓共有外生機會沿用同一亂數鍵，資格、權重與事件集合仍可能隨選擇改變。比較是模型內的假設，不是現實因果證明。

## 引擎與存讀契約

- `LifeSession.beforeDecision(at:)` 先驗證原歷史，再重播到指定索引的選擇前。索引按決策時點而不是事件 ID，支援同一事件跨年齡重複。
- `LifeSnapshot` 保存選前完整 session、決策索引與亂數版本；內含國家、家庭、Seed、引擎／資料／內容版本、待觸發線索、人物關係、故事事實、決策與事件抽選 trace。
- `BranchExperiment` 的原局與快照不可變，只有替代人生能推進。原局必須已結束，替代選擇必須不同且可行；不複製原局未來。舊線索仍到期一次，改選取消的原路未來線索不會流入替代局。
- 兩路的共同前綴、分岔事件與原背景綁定都會驗證。直接 Codable 解碼不等於受信任；操作／比較／載入會驗證版本與完整重播，拒絕偽造 metadata、快照或人生。
- 分岔版本 `branch-experiment-1`、存檔 schema `1` 與既有 `rng-v2-1` 引擎分開；本片沒有變更事件抽選、40事件內容或既有亂數演算法。
- `LifeJourney` 是單局或一組分岔，不重複儲存可變 active session；`LifePersistence` 是純值 Domain 之外的檔案介面。保存完整組合後才提交 UI 狀態，失敗不吃掉玩家的操作。
- 缺檔返回未建立存檔；損壞、不相容及讀寫錯誤明確回報並保留原檔。不做無聲遷移或重新開始。LC-06 的 SwiftData、多存檔與廣泛裝置驗收另列。

## 驗證與重現

- `swift test -c release`：所有舊測試加 LC-04 引擎與實際磁碟存讀測試。
- `swift run -c release life-demo --branch-sample`：正式40事件目錄、日本家庭一、Seed 0、13歲線上改紙本，其後測試工具選休息；工具明示策略，App 不代選。輸出原局、選前快照、完整替代局、逐時點比較及重播／Codable結果。
- `bash scripts/ios-check.sh`：小螢幕完整人生、13歲改選、終止與重開 App、原人生查看、走完後半生並比較到最後年齡，專用 Simulator 退出時刪除。
- 記憶與測試使用 canonical writer／receipt。測試修復過程保留失敗原因；不把試玩、實機或人工 VoiceOver 當成已通過。

初次 focused 測試的延遲線索案例誤以為正式8／10歲會排入 callback；實際規則只在較後年齡排入。已改為明示的8→12、10→14歲 fixture，專門驗證分岔前仍有效線索與被改選線索的保留／排除；沒有為讓測試過關修改正式故事內容。

## 本輪驗證結果

- Swift：全套86項（75 Domain／6 Analysis／5 Persistence）通過，後補1項不同背景配對拒絕測試，11項BranchExperiment定向重跑全通過，共87個不同案例；沒有把重跑重複算入總數。既有1,000人生與三條故事鏈測試保持。
- Python：15項通過；新CLI模式使舊測試harness的switch漏分支，修正harness並驗證新參數／衝突參數後通過。初次失敗收據保留。
- UI：首次六項中五項通過，包括完整分岔／重開續玩／比較到晚年。既有重新開始測試遇到系統同按鈕雙重accessibility節點，定位加入label與firstMatch，單項定向重跑通過。不是兩次全套成功。
- 兩次均使用iPhone SE第三代／iOS27專用裝置，成功或失敗後都已刪除，另核對inventory沒有殘留；未刪其他裝置或runtime。
- 基本檢查六項、離線資料生成一致性、CLI完整分岔樣本及git diff格式檢查通過。未做實機或人工VoiceOver驗收。
